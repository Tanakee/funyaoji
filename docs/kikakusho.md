# ふにゃおじ 企画書

11/18 のミーティングで決めたことを入れた版。

## ひとことで

**会場のみんなのスマホで、「ふにゃふにゃのおじさん」を操り人形のように動かして、みんなで走らせる。**

## 体験

1. 大画面（PC のブラウザ）に出た QR コードを、スマホで読んで参加する（アプリは入れなくてよい）
2. 4人が、おじさんの左右のひざ・もも（股関節）の4か所を、1人1か所ずつ担当する
3. スマホを傾けると、担当の関節が動く。スマホから大画面に糸が出ているイメージで、水平に持ったスマホを立てる（手前に倒す）と糸が引っ張られる。入力が効いているかは、画面の色で分かる
4. 4人の動きが合わさって、おじさんが走る。息が合わないと転ぶ
5. 50m を走りきるまでのタイムを測り、ランキングに出す

おじさんは1体。まずは4人そろうまで遊べない形で作る。

## この案のいいところ

- **シンプル**：「みんなでおじさんを走らせる」の一言で伝わる
- **みんなが参加できる**：スマホがあれば、審査員も会場の人もその場で入れる
- **自分が動かしている実感がある**：1人が1か所を担当し、入力が効いているかが画面の色で見える
- **技術的に面白い**：軸は、みんなの傾きをリアルタイムにおじさんの動きへ反映する通信。その次に物理演算
- **テーマ「ito」に合う**：スマホ1台1台が、おじさんを動かす操り人形の「糸」になる
- **審査で狙える**：配点の大きい「完成度・デモプレイ」（100点中40点）と「WOW 度」（30点）

## 仕組み

```
スマホ（4台）  ──傾き──→  サーバー  ──4人の入力──→  大画面
傾きを読んで連続で送る      全員がつながる場所          入力でおじさんを動かして映す
```

スマホの入力は傾き、見た目は 2D に決めた。通信とおじさんの体に何を使うかは、これから設計で決める。

| 部品 | 役目 | 決まったこと・候補 |
|---|---|---|
| スマホの入力 | 傾きを読み、連続で送る | 傾きに決定（スマホのブラウザで取れる） |
| 通信 | 4人の傾きを、リアルタイムに大画面へ届ける | 候補：WebSocket、Cloudflare の Durable Objects、Redis |
| おじさんの体 | おじさんを動かして映す | 2D に決定（ペーパーマリオのようなリッチな表現）。候補：2D の物理演算（Matter.js、Rapier）、Godot |

## 作る範囲

- **最低限**：4人がスマホから参加し、傾きで担当の関節を動かせる。おじさんが 50m を走り、タイムとランキングが出る。デバッグ用に、キーボードでも動かせる
- **次に**：物理演算で、ふにゃふにゃの動きを面白くする。2D の見た目をリッチにする
- **ゲームができてから**：強化学習で、このゲームの理論値（うまく動かしたときの最速のタイム）を調べる

## デモ

5分のデモで、プレイ動画を見せつつ実際に遊んでもらい、技術のこだわりを話す。誰に遊んでもらうかなど、流れはまだ決めていない。
