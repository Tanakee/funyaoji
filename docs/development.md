# 開発の進め方

## 流れ

1. やることは GitHub の Issue にする。1 Issue は、1人が半日〜1日で終わる大きさにする
2. 担当する Issue に自分を Assignees で付ける
3. main からブランチを切る。名前は `<Issue 番号>-<短い英語>`（例：`12-tilt-input`）
4. PR を出す。本文に `Closes #12` を書くと、マージで Issue が閉じる
5. 誰か1人が見て OK なら、Squash and merge する。マージしたらブランチを消す

- main に直接 push しない
- 小さくてもいいので、早めに PR を出す。途中なら Draft で出す

## コミットメッセージ

日本語で1行。何をしたかが分かればよい（例：`スマホの傾きを読んでサーバーに送る`）。

## ラベル

Issue と PR に、種類を1つ、場所を1つ以上付ける。

| ラベル | 意味 |
|---|---|
| `feature` | 新しい機能 |
| `bug` | 不具合 |
| `docs` | ドキュメント |
| `chore` | 設定・環境など、機能に関わらない作業 |
| `area: screen` | 大画面（PC のブラウザ）のフロント |
| `area: phone` | スマホのフロント（傾きを読む・送る） |
| `area: server` | サーバー・通信 |
| `area: infra` | デプロイ・インフラ |
| `MVP` | 最低限の動く版に要るもの。先にやる |
| `good first issue` | 初めての人でも取りかかりやすい |
