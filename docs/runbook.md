## 発表の最中

ログを見る人は、手元でログを流しておく。

```sh
npx cf observability tail --worker funyaoji
```

- 1人が流せるのは、1つの Worker につき1本だけ
- 残るのは、サーバーが書いた出来事と例外だけ。`tilt` と `pong` ではログが出ない（[設計](design.md) の「ログ」）
- ログは `{ roomCode, event, ... }` の形。発表で使っているルームコードで見分ける

見るログ：

| `event` | 意味 | 見たらどうするか |
|---|---|---|
| `connected` | 接続した。スマホなら `joint`（関節）と、`returning`（予約か置き換えで関節を取り戻したか）が付く | 4台そろうまで待つ |
| `rejected` | 参加を断った。`reason` が `full`・`playing`・`no-room` | 下の「スマホがつながらない」 |
| `closed` | 接続が閉じた。`code` が close コード | 下の表 |
| `timeout` | ハートビートもメッセージも15秒届かなかったので閉じた（そのあと `closed` の `4002`） | その台の画面のロック・電波を確かめる。つなぎ直しを待つ |
| `reserved` | 切れたスマホの関節を60秒とっておいた | 60秒以内に戻れば、同じ関節に戻る |
| `replaced` | 同じスクリーンか、同じ ID のスマホの新しい接続に置き換えた | スクリーンの `replaced` は、別の画面で同じルームを開いたということ |
| `phase` | スクリーンが送った状態（`lobby`・`playing`・`result`） | 進行の確認 |
| `error` | 例外 | 内容を控える。続くなら下の「本番で問題が起きた」 |

`closed` の close コード（[API](api.md)）：

| コード | 意味 |
|---|---|
| `4000` | 新しい接続に置き換えた（スクリーン、または同じ ID のスマホ）。つなぎ直さない |
| `4001` | 参加を断った（`rejected` のあと） |
| `4002` | ハートビートもメッセージも15秒届かなかった。クライアントはつなぎ直す |
| そのほか | ページを閉じた・回線が切れたなど。クライアントはつなぎ直す |

## 困ったとき

| 症状 | 原因の候補 | やること |
|---|---|---|
| 本番で問題が起きた（ページが開かない、`error` が続く） | 直前のデプロイの不具合 | 前のバージョンに戻す（下の「バージョンを戻す」）。戻したら、スクリーンとスマホで遊べるかを確かめる |
| 会場の Wi-Fi が使えない | 回線の混雑・不調 | スクリーンの PC とスマホを、別の回線（テザリングなど）につなぐ。サーバーは Cloudflare にあるので、インターネットにつながれば動く。回線を替えると接続が切れるが、スマホもスクリーンも同じルームに自動でつなぎ直す。スマホは60秒以内なら同じ関節に戻る |
| スマホがつながらない（`full`） | 4つの関節が、接続中のスマホか予約で埋まっている。切れたスマホの関節は60秒予約される | 余分な台が入っていないかを、スクリーンの関節の表で見る。予約が切れる60秒を待ってから、QR コードを読み直す |
| スマホがつながらない（`playing`） | プレイ中は、新しいスマホを受け付けない | 結果かロビーに戻るのを待つ。スマホは自動でつなぎ直す |
| スマホがつながらない（`no-room`） | スクリーンを開き直して、別のルームになった。または、誰も接続しないまま10分たち、ルームが消えた | 今のスクリーンに出ている QR コードを読み直す |
| スマホがつながらない（理由が出ない） | 回線、傾きの読み取りが許可されていない | 回線を確かめる。ページを開き直し、傾きの読み取りを許可する |
| スクリーンが切れた（「切れたので、つなぎ直しています」） | 回線の途切れ | 待つ。同じルームに自動でつなぎ直す。プレイ中だったときは、ロビーに戻る。ページを開き直すと新しいルームになり、全員が QR コードを読み直すことになるので、つなぎ直せないときだけ開き直す |
| スクリーンが「切れた（close コード 4000）」 | 別の画面（別のタブ・別の PC）で同じルームのスクリーンを開いた | 使う画面を1つに決める。古い画面はつなぎ直さない |
| 1日の上限に届いた | Durable Objects のリクエストが上限を超えた。ルームの作成・接続・メッセージの中継が、どれもルームの Durable Object を通るので、遊べなくなる | 日本時間の朝 9 時まで戻らない。TODO：対策は [#65](https://github.com/Tanakee/funyaoji/issues/65) で決める（プレイ動画で代える、など） |
| ログが出なくなった | ログ（Workers Logs）の1日の上限に届いた。ゲームは動く | ゲームは続ける。あとから調べられないので、気づいたことを手で控える |

### バージョンを戻す

戻せるのは、Super Administrator か Workers Platform Admin のロールを持つ人だけ。手順の詳しいところは [Rollbacks](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/) にある。

ダッシュボードで戻す：Workers & Pages → `funyaoji` → Deployments で、戻したいバージョンを選んで戻す。

`cf` で戻す：

```sh
# 今のデプロイ（一覧の先頭が、今動いているもの）と、バージョンの一覧を見る
npx cf workers deployments list --worker funyaoji
npx cf workers versions list --worker funyaoji

# 戻したいバージョンを、100% で動かす
npx cf workers deployments create --worker funyaoji \
  --versions '[{"version_id":"<戻したいバージョンの ID>","percentage":100}]'
```

- Durable Objects のクラスを足した・消したバージョンをまたいでは、前のバージョンに戻せない
- 戻すと、本番の内容が `main` とずれる。直した変更を `main` に入れると、また最新の `main` がデプロイされる
- GitHub Actions が使えないときだけ、ローカルからデプロイする（`npx cf deploy`）。コミットしていない変更も本番に出るので、`main` と同じ状態で行う
