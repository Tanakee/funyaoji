### ランキングを空にする

リハーサルが終わったら、発表の前に1回だけ、ランキングを空にする。リハーサルや開発中の記録を、発表で出さないため（[設計](design.md) の「ランキング」）。

1. `src/server/index.ts` の `RANKING_SEASON` を、本番でまだ使っていない値（発表の日付の `"2026-11-28"` など）に変える PR を出し、マージする。前に使った値（`dev` など）に戻すと、そのときの記録がまた見える
2. マージしてできた `main` のコミットで、CI と本番のデプロイが通ったことを確かめる。下の2つが、どちらも success になるまで待つ

   ```sh
   git fetch origin && sha=$(git rev-parse origin/main)
   gh run list --commit "$sha" --workflow ci.yml
   gh run list --commit "$sha" --workflow deploy.yml
   ```

3. その Deploy のログ（`gh run view <Deploy の run ID> --log`）に出る `Current Version ID` が、`npx cf workers deployments list --worker funyaoji` の先頭（100% で動いているもの）のバージョンと同じかを確かめ、その ID を控える。これより前のバージョンには戻さない（下の「バージョンを戻す」）
4. 会場の回線から、ランキングが空なのを確かめる

```sh
curl --fail --show-error 'https://funyaoji.team-sweater.workers.dev/api/rankings?mode=10m'
# {"mode":"10m","rankings":[]} なら空
```

- 前のシーズンの記録は消えずに、前の名前の Durable Object に残る。値を戻せば、また見える
- シーズンを入れた PR（#97）のマージで、名前が `rankings` から `rankings-dev` に変わる。それまでの記録は表示から外れる（消えてはいない）
- マージを止めている時間（上の「前日まで」の TODO）でも、この PR だけは入れる。デプロイの時間を見込んで、発表の前に余裕を持って行う

## 発表の最中

ログを見る人は、手元でログを流しておく。

```sh
npx cf observability tail --worker funyaoji
```

- 1人が流せるのは、1つの Worker につき1本だけ
- 残るのは、サーバーが書いた出来事と例外だけ。`tilt` と `pong` ではログが出ない（[設計](design.md) の「ログ」）
- ログは `{ roomCode, event, ... }` の形。発表で使っているルームコードで見分ける
- 捕まえていない例外は、`event` の無い別の形のログで出る

見るログ：

| `event` | 意味 | 見たらどうするか |
|---|---|---|
| `connected` | 接続した。スマホなら `joint`（関節）と、`returning`（予約か置き換えで関節を取り戻したか）が付く | 4台そろうまで待つ |
| `rejected` | 参加を断った。`reason` が `full`・`playing`・`no-room` | 下の「スマホがつながらない」 |
| `closed` | 接続が閉じた。`code` が close コード | 下の表 |
| `timeout` | ハートビートもメッセージも15秒届かなかったので閉じた。相手から close が返ったときだけ、そのあと `closed` の `4002` が出る（画面のロックや電波切れでは返らないので出ない） | その台の画面のロック・電波を確かめる。つなぎ直しを待つ |
| `reserved` | 切れたスマホの関節を60秒とっておいた | 60秒以内に戻れば、同じ関節に戻る |
| `replaced` | 同じスクリーンか、同じ ID のスマホの新しい接続に置き換えた | 同じ画面が自分でつなぎ直したときにも出る（クライアントは10秒で切れたと見なし、サーバーが閉じるのは15秒なので、回線が10〜15秒止まると起きる。回線を替えたときも）。スマホなら `returning: true` も付く。別の画面に置き換えられたと言えるのは、スクリーンに「切れた（close コード 4000）」と出たときだけ |
| `phase` | スクリーンが送った状態（`lobby`・`playing`・`result`） | 進行の確認 |
| `error` | WebSocket のエラー（`webSocketError` が書く） | 内容を控える。続くなら下の「本番で問題が起きた」 |

`closed` の close コード（[API](api.md)）：

| コード | 意味 |
|---|---|
| `4000` | 新しい接続に置き換えた（スクリーン、または同じ ID のスマホ）。つなぎ直さない |
| `4001` | 参加を断った（`rejected` のあと） |
| `4002` | ハートビートもメッセージも15秒届かなかった。クライアントはつなぎ直す |
| そのほか | ページを閉じた・回線が切れたなど。クライアントはつなぎ直す |

## 困ったとき

| 症状 | 原因の候補 | やること |
|---|---|---|
| 本番で問題が起きた（ページが開かない、`error` や例外が続く） | 直前のデプロイの不具合 | 前のバージョンに戻す（下の「バージョンを戻す」）。ランキングを空にしたあとは、同じシーズンのバージョン（上の「ランキングを空にする」で控えた ID か、それより後のもの）にだけ戻す。そういうバージョンが無いときは、戻さずに直したものをデプロイする。戻したら、スクリーンとスマホで遊べるかを確かめる |
| 会場の Wi-Fi が使えない | 回線の混雑・不調 | スクリーンの PC とスマホを、別の回線（テザリングなど）につなぐ。サーバーは Cloudflare にあるので、インターネットにつながれば動く。回線を替えると接続が切れるが、スマホもスクリーンも同じルームに自動でつなぎ直す。スマホは60秒以内なら同じ関節に戻る |
| スマホがつながらない（`full`） | 4つの関節が、接続中のスマホか予約で埋まっている。切れたスマホの関節は60秒予約される | 余分な台が入っていないかを、スクリーンの関節の表で見る。予約が切れる60秒を待ってから、QR コードを読み直す |
| スマホがつながらない（`playing`） | プレイ中は、新しいスマホを受け付けない | 結果かロビーに戻るのを待つ。スマホは自動でつなぎ直す |
| スマホがつながらない（`no-room`） | スクリーンを開き直して、別のルームになった。または、誰も接続しないまま10分たち、ルームが消えた | 今のスクリーンに出ている QR コードを読み直す |
| スマホがつながらない（理由が出ない） | 回線 | 回線を確かめる。ページを開き直す |
| スマホに「傾きの読み取りが許可されていません」 | 許可の画面で「許可しない」を押した。iPhone はブラウザを開き直すまで、もう一度は許可の画面を出さない | 画面に出る手順どおり、ブラウザを終了して開き直し、QR コードを読み直して「許可」を押す |
| 動きがカクつく・反応が遅い | スマホの低電力モード（送信が半分くらいに落ちる）。回線が遠い拠点につながっている（上の「当日の朝」の `colo`） | 低電力モードを OFF にしてもらう。スクリーンの「遅延（最新 / 中央値）」と `colo` を見る |
| スクリーンが切れた（「切れたので、つなぎ直しています」） | 回線の途切れ | 待つ。同じルームに自動でつなぎ直す。プレイ中だったときは、ロビーに戻る。ページを開き直すと新しいルームになり、全員が QR コードを読み直すことになるので、つなぎ直せないときだけ開き直す |
| スクリーンが「切れた（close コード 4000）」 | 別の画面（別のタブ・別の PC）で同じルームのスクリーンを開いた | 使う画面を1つに決める。古い画面はつなぎ直さない |
| 1日の上限に届いた | Durable Objects のリクエストが上限を超えた。ルームの作成・接続・メッセージの中継が、どれもルームの Durable Object を通るので、遊べなくなる | 日本時間の朝 9 時まで戻らない。TODO：対策は [#65](https://github.com/Tanakee/funyaoji/issues/65) で決める（プレイ動画で代える、など） |
| ログが出なくなった | ログ（Workers Logs）の1日の上限に届いた。ゲームは動く | ゲームは続ける。あとから調べられないので、気づいたことを手で控える |

### バージョンを戻す

戻せるのは、Super Administrator か Workers Platform Admin のロールを持つ人だけ。手順の詳しいところは [Rollbacks](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/) にある。

ダッシュボードで戻す：Workers & Pages → `funyaoji` → Deployments で、戻したいバージョンを選んで戻す。

`cf` で戻す：

```sh
# 今のデプロイ（一覧の先頭が、今動いているもの）と、バージョンの一覧を見る
npx cf workers deployments list --worker funyaoji
npx cf workers versions list --worker funyaoji

# 戻したいバージョンを、100% で動かす
npx cf workers deployments create --worker funyaoji --strategy percentage \
  --versions '[{"version_id":"<戻したいバージョンの ID>","percentage":100}]'
```

- Durable Objects のクラスを足した・消したバージョンをまたいでは、前のバージョンに戻せない
- ランキングを空にしたあとは、そのデプロイ（上の「ランキングを空にする」で控えた ID）以降のバージョンにだけ戻す。それより前に戻すと、リハーサルの記録のシーズンに戻り、発表で保存した記録が見えなくなる
- 戻すと、本番の内容が `main` とずれる。直した変更を `main` に入れると、また最新の `main` がデプロイされる
- GitHub Actions が使えないときだけ、ローカルからデプロイする（`npx cf deploy`）。コミットしていない変更も本番に出るので、`main` と同じ状態で行う
