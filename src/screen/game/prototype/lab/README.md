# 試作の検証の道具（あとで捨てる）

ふにゃおじの体と操作の設定を、Node だけで測り、動画にする道具。ブラウザと開発サーバーは使わない。

## 何を測るか

本番は、4人がスマホを傾けて、4つの関節（右もも・左もも・右ひざ・左ひざ）を1人1つずつ動かす。4人の息は合わない。そこで、次の2つを使って測る。

- 歩き方の機械（`../bot.ts` の `gaitInput`）：脚を交互に振る入力を作る。値は周期 `T`、ももの中心 `h0`、ももの振り幅 `A`、ひざの曲げ `K`、ひざのタイミング `kp`
- ずれ（`makeNoise`）：関節ごとに、タイミングのずれ（秒）と、動かす幅のずれを足す。4人の息の合わなさの代わり。大きさは `run.ts` の `NOISE_LEVELS`（小・中・大）

主な物差しは「ずれ中で、16回のうち何回 10m に着くか」。`evaluate()` は、歩き方を乱数で探し、ずれ中に強いものを選んで、小・中・大で16回ずつ走らせる。

走りの終わり方は4つ。

| 終わり方 | 意味 |
|---|---|
| `goal` | 胴が 10m に着いた |
| `fell` | 胴か頭が地面に触れた |
| `stuck` | 6秒のあいだに 0.3m 進まなかった（座り込むなど） |
| `timeout` | 30秒たった |

異常の検出（ゴールしても、これに引っかかるものは数えない、または「異常」として数える）。

- `sanity()`：平均の速さ 2.5m/s より速い、最大の速さ 5m/s より速い、胴が 0.25m より跳ね上がる、両足が浮いている時間が3割を超える。物理の計算が不安定になると、このどれかが出る
- `agency()`：関節を1つずつ中立の入力で止めて走らせる。それでも 10m に着く関節があれば、その関節の人は操作しなくてよいことになる（`walksWithout` に出る）

## 今の値（2026-11-24 時点）

`DEFAULT_PARAMS` に `assist: 2` の設定は、乱数の歩き方 300 個のうち 2 個しか 10m に着かず、ずれ中では 0/16。失敗のほとんどは転倒ではなく `stuck`（尻もちをついて座り込む）。

## コマンド

funyaoji のリポジトリのルートで動かす。

```sh
# 候補（設定＋歩き方）を測る。歩き方は探し直し、--out に結果入りの候補を書く（1つ数秒〜30秒）
node src/screen/game/prototype/lab/eval.ts <候補.json> --out <結果の候補.json>

# 候補を1回走らせて記録する。--noise でずれを足す（seed は 1〜16 が、計測と同じ種）
node src/screen/game/prototype/lab/candidate.ts <候補.json> <記録.json> [--noise mid --seed 3]

# 記録を動画にする。複数渡すと並べて同時に再生する。--sheet で12コマを並べた PNG も作る
node src/screen/game/prototype/lab/render.ts --out <名前> [--gif] [--sheet] [--cols 2] <記録.json> ...
```

候補の JSON の形（`candidate.ts` の `Candidate`）。`params` は `DEFAULT_PARAMS` との差分だけ書く。`body` も差分でよい。

```json
{
  "label": "今のお手本",
  "note": "目標角度のモーター、胴を起こす補助 2",
  "params": { "assist": 2, "body": { "thigh": { "hh": 0.25 } } },
  "gait": { "T": 1.43, "h0": 0.23, "A": 0.4, "K": 0.85, "kp": 0.09 }
}
```

自分で計測のスクリプトを書くときは `run.ts` を import する（`evaluate`・`run`・`robustness`・`agency`・`sanity`）。

## 動画の見方

- 左上：候補の名前、説明、距離と時間
- 右上：4つの関節の入力（色の棒）と、実際の角度（黒い線）。棒と線が離れているほど、モーターが追いついていない
- 右下：足が地面に着いているか（塗りつぶしの丸が着いている）
- 終わったら「ゴール」「転倒」「止まった」「時間切れ」と、`sanity()` で引っかかった異常を出す
